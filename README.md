# SpinTextureTheoryAgent

A Mathematica/Wolfram-Language-centered theory agent for deriving magnetic texture dynamics from high-level physical descriptions.

> **Research portfolio role: Project 1.** This repository is the teacher-proposed,
> publication-first symbolic-derivation project. It must pass the Project 1 completion
> gate before implementation begins in Project 2, `SpinTextureExperimentAgent`.

## Goal

Convert a structured or natural-language physics request such as:

```text
material: collinear antiferromagnet
texture: stripe domain
drive: spin-orbit torque
geometry: 2D thin film
goal: collective-coordinate dynamics and stability
```

into:

1. a selected order parameter and Hamiltonian template;
2. a continuum energy functional;
3. Wolfram Language code for variational derivatives;
4. collective-coordinate projection;
5. linear-stability and topological-charge analysis;
6. a reproducible report skeleton.

## Unified application contract

Project 1 is one agent with one Physics IR, derivation engine, validation chain,
and provenance record. It is not split by user type. For a supported problem
family, it produces a complete reproducible derivation. For an unseen material
or texture, it produces a provisional, inspectable Physics IR and derivation
route, records missing symmetry or boundary evidence, and requires review before
the route can become formally supported.

The same authoritative record may be rendered as a formal theory report or an
accessible explanation for experimental and other non-theory users. Presentation
must never change formulas, hide assumptions, or convert a candidate result into
a validated claim. See
[docs/PROJECT_1_APPLICATION_CONTRACT.md](docs/PROJECT_1_APPLICATION_CONTRACT.md).

## Current scope

This first version focuses on symbolic theory derivation only. It does **not** run micromagnetic or atomistic simulations.

Supported initial templates:

- Ferromagnet + axisymmetric skyrmion + SOT: Wolfram-derived Thiele dynamics.
- Ferromagnet + elliptic antiskyrmion + SOT: anisotropic-DMI Thiele dynamics.
- Collinear antiferromagnet + stripe domain + SOT: sigma-model and domain-wall-array dynamics.
- Collinear antiferromagnet + skyrmion: inertial collective-coordinate dynamics.
- Meron, bimeron, and vortex: boundary-conditioned Wolfram topology derivations.

Every Physics IR record declares one of four support levels:

- `full_derivation`: end-to-end terminal equation is generated from executable symbolic steps;
- `scaffold`: model routing and selected symbolic substeps are implemented, but terminal results still include templates or prescribed forms;
- `review_only`: the agent identifies the required theory and safety checks but does not claim a symbolic result;
- `unsupported`: no validated route is currently available.

At the current stage, all three configured core benchmarks (AFM stripe + SOT, FM skyrmion + SOT,
and AFM skyrmion + SOT) are
`full_derivation` routes. The stripe route's wall metric, mass, damping, SOT generalized force, periodic-chain
Hessian, and differential equations are generated by Wolfram calculations. This classification is
conditional on the recorded rigid-wall, pinned-angle, periodic-chain, explicit-force-density, and
phenomenological-stiffness assumptions. The FM skyrmion route derives its boundary-conditioned
topological charge, angular gyrotropic and dissipative projections, LLG-SOT force, and first-order
Thiele equations for a rigid axisymmetric unit-winding texture with fixed helicity and in-plane spin
polarization. The AFM skyrmion route derives its inertial mass and damping tensors, sigma-model SOT
force, opposite-sublattice gyrotropic cancellation, and second-order equations under the corresponding
compensated and translationally invariant assumptions. Complex magnetic orders and unspecified DMI
remain `review_only`. A benchmark pass means the case satisfied the
criteria for that declared level, not that an assumption-free new physical result was proved.

All seven `full_derivation` routes currently have `cas_execution=passed`,
`analytic_reproduction=passed`, `assertion_coverage=passed`, and bounded,
hash-verified SymPy/mpmath `cross_engine=passed` evidence. Benchmark cases are
`registered`, not passed, and external review is pending. The displayed
`cas_validated` knowledge status is a derived compatibility summary, not an
independent evidence axis. See
[docs/EVIDENCE_GOVERNANCE.md](docs/EVIDENCE_GOVERNANCE.md). Core-three and
extended routes use independently implemented cross-engine checks.

The configured antiskyrmion route is also `full_derivation` under a winding-minus-one elliptic
ansatz aligned with the anisotropic-DMI principal axes. Wolfram derives `Q=polarity`, the
`lambdaX/lambdaY` dissipative tensor, anisotropically scaled SOT force, projected DMI helicity
dependence, isotropic-shape limit, and the resulting first-order Thiele equations. It does not claim
arbitrary magnetic point groups or unconstrained texture deformation.

The meron topology route derives `Q=polarity*winding/2` from explicit core and in-plane far-field
boundaries. The vortex route independently derives the closed-contour winding number and records why
it is distinct from a core-polarity-dependent half charge. Both routes include dimensionless-invariant
checks and retain scaffold behavior when boundary data are absent.

The bimeron route derives the additive constituent formula
`Q_bi=(p1*w1+p2*w2)/2`. Under the explicitly declared nontrivial pairing
`p2=-p1`, `w2=-w1`, it verifies `Q_bi=p1*w1` and `|Q_bi|=1`; an equal-polarity,
opposite-winding control pair gives zero charge. This route assumes an inspectable, sufficiently
separated two-meron decomposition and requests direct full-field integration when the cores strongly
overlap.

The FM and AFM SOT projections intentionally use different declared conventions. The FM LLG route
projects a torque with `tau . (m cross partial_q m)`, whereas the AFM sigma-model route projects the
declared force density with `f . partial_q n`. Consequently, which named torque channel survives the
rigid-translation projection is convention-dependent and must not be compared without this metadata.

The AFM stripe route also carries an executable dimensional contract in its Physics IR. Under the
one-dimensional energy-per-transverse-area convention, Wolfram checks that exchange, anisotropy,
and DMI densities all have dimension `E L^-1`; every term in the wall-translation equation has
dimension `E L^-1`; and every term in the internal-angle equation has dimension `E`. These checks
are stored as structured results and are required by the benchmark evaluator.

## Quick start

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e .
python -m spintexture_agent.cli run configs/afm_stripe_sot.yaml
```

Inspect the auditable capability boundary before running a task:

```bash
python -m spintexture_agent.cli capabilities
python -m spintexture_agent.cli capabilities \
  --material collinear_antiferromagnet \
  --texture stripe_domain
python -m spintexture_agent.cli capabilities --support-level full_derivation --json
```

Run the optional independent SymPy/mpmath core-three checks with:

```bash
python -m pip install -e '.[cross-engine]'
python -m spintexture_agent.cli cross-engine run \
  --out analysis/cross_engine/core3_reproduction_01 \
  --require-pass
python -m spintexture_agent.cli cross-engine run \
  --suite extended \
  --specs cross_engine_specs/extended \
  --out analysis/cross_engine/extended_reproduction_01 \
  --require-pass
```

The capability registry is stored in `knowledge_base/capabilities.yaml`. A task
that does not match a registered route cannot inherit `full_derivation` merely
because it resembles an existing template; it is downgraded to a candidate and
receives missing-evidence and promotion requirements.

Regenerate the manuscript-facing claim boundary from the same registry:

```bash
python -m spintexture_agent.cli capabilities \
  --claim-matrix docs/PROJECT_1_CLAIM_EVIDENCE_MATRIX.md
```

The YAML `run` command generates a task bundle under `outputs/` containing:

- `notebooks/<task>.wl`: generated Wolfram Language derivation script;
- `summaries/<task>_summary.md`: one layered accessible/formal report generated from the same task record;
- `records/<task>_record.json`: authoritative structured record containing record ID, capability status, Physics IR, validation, artifact contract, and Wolfram execution status.

You can also start from a controlled natural-language prompt. The parser is intentionally
conservative: it extracts material, texture, drive, geometry, goals, assumptions, and parameters,
then lets the Physics IR and validator expose uncertainty rather than silently guessing.

```bash
python -m spintexture_agent.cli parse \
  "二维反铁磁薄膜中，SOT 驱动条纹畴，推导条纹畴动力学方程并分析稳定性。" \
  --show-plan
```

To go directly from prompt to derivation bundle:

```bash
python -m spintexture_agent.cli run-prompt \
  "二维反铁磁薄膜中，SOT 驱动条纹畴，推导条纹畴动力学方程并分析稳定性。" \
  --out outputs/natural_language_demo \
  --save-config outputs/natural_language_demo/afm_stripe_sot.yaml
```

Optionally request Wolfram execution:

```bash
python -m spintexture_agent.cli run configs/afm_stripe_sot.yaml --execute-wolfram
python -m spintexture_agent.cli run-prompt \
  "AFM skyrmion under SOT in a 2D thin film; derive the collective-coordinate dynamics and topology." \
  --execute-wolfram
```

If `wolframscript` or `WolframKernel` is unavailable, execution is recorded as `skipped` and an
execution-requested benchmark case is marked `incomplete`, not passed.

## Independent evidence validation

The core-three symbolic claims are checked through two separately implemented
Wolfram paths:

1. the generated agent script, which uses the project derivation package; and
2. an independent analytic gold script, which must not load that package.

Run all registered core-three Evidence Cards with:

```bash
python -m spintexture_agent.cli evidence \
  --cards evidence_cards/core3 \
  --out analysis/evidence_runs/core3_latest \
  --wolfram-timeout 240
```

The command compares selected equations, tensors, topology results, boundary
limits, and regression flags, then writes `evidence_result.json` and
`evidence_summary.md` for each route. Process exit alone is never treated as
symbolic correctness. Expert approval is a separate recorded gate.

The antiskyrmion, meron, bimeron, and vortex Evidence Cards are reproduced with
the same protocol by replacing `evidence_cards/core3` with
`evidence_cards/extended`. The source-located run is stored under
`analysis/evidence_runs/extended_literature_01`.

Run the deterministic machine-physics audit over the frozen core-three evidence:

```bash
python -m spintexture_agent.cli machine-audit \
  --specs machine_audit_specs/core3 \
  --evidence-runs analysis/evidence_runs/core3_latest \
  --out analysis/machine_audit/core3_latest
```

The audit separates formal-route consistency from material applicability. It
checks continuum symmetry choices, source-linked literature alignment,
dimensions, boundaries, limits, topology, and counterfactual model mutations.
A separate `literature_reproduction` badge requires equation/page locators,
hashed source expressions, blinded symbol mappings, explicit convention
transforms, and executable source-to-target assertions. Exact claims are typed
as `exact_coefficient`, `exact_normalized`, or `boundary_conditioned_exact`;
structural and partial alignment remain bounded non-coefficient claims. All
seven full routes currently pass this executable gate. See
[docs/EXTENDED_LITERATURE_REPRODUCTION_PROTOCOL.md](docs/EXTENDED_LITERATURE_REPRODUCTION_PROTOCOL.md).
A material-specific symmetry pass additionally requires a typed
`MaterialSymmetryRecord` bound to an external symmetry artifact by SHA-256;
arbitrary material labels in a task config cannot satisfy this gate.

The current generic core-three tasks return `formal_route=pass`,
`material_applicability=incomplete`, and `overall=conditional_pass` because no
named magnetic structure, magnetic space group, or sourced SOT response tensor
is supplied. Machine-audit results populate independent evidence axes and do not
imply an external-review pass.

Audit whether every full-route Wolfram result is explicitly classified and
whether dimension, sign, boundary, and limit assertions are executable with:

```bash
python -m spintexture_agent.cli assertion-coverage \
  --evidence-runs \
    analysis/evidence_runs/core3_latest \
    analysis/evidence_runs/extended_literature_01 \
  --out analysis/assertion_coverage/literature_02 \
  --require-complete
```

The report keeps `pass`, `not_applicable`, and `missing` separate and rejects
fatal Wolfram sentinels in every result class. Intentionally held coefficient
integrals must be declared `symbolic_by_design`; they are not silently counted
as closed-form results. See
[docs/ASSERTION_COVERAGE_PROTOCOL.md](docs/ASSERTION_COVERAGE_PROTOCOL.md).

## Development strategy

Work with Codex in small steps:

1. scaffold package and tests;
2. implement YAML and controlled natural-language parsing plus template selection;
3. implement Wolfram template generation;
4. implement checker rules;
5. add example derivations;
6. expand physics templates only after tests pass.
